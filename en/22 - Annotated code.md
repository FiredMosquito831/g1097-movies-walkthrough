## 22.1 `Movie.java` — the model

### The complete file, annotated

```java
package ro.ase.ie.g1097.model;          // the `model` subpackage — clean data

import java.io.Serializable;            // marker: the object can be sent through an Intent
import java.util.Date;                  // the type of the release date

public class Movie implements Serializable {
```

**Why `implements Serializable`:** `Intent.putExtra(String, Serializable)` is the only simple way to send a whole object between two activities. Without it, `putExtra(MOVIE_EXTRA, movie)` does not compile.

**Why it has no `import android.*`:** the model has to be testable without an emulator. If it imported `EditText`, it would depend on the UI.

```java
    private String title;        // EditText
    private Date release;        // date EditText
    private String genre;        // Spinner
    private double budget;       // number EditText
    private int duration;        // SeekBar
    private float rating;        // RatingBar
    private boolean watched;     // Switch
    private String approval;     // RadioGroup | RadioButtons
    private boolean onWatchlist; // Checkbox
    private String poster = null;
```

**The comments on the right are the professor's documentation:** every field notes **which widget** produces it. You keep them — in the exam, the question "where does field X come from?" has its answer right there in the code.

**Why each type:**

| Field | Type | Why |
|---|---|---|
| `title` | `String` | free text from `EditText` |
| `release` | `Date` | a date, so you can compute differences |
| `genre` | `String` | the text selected in the `Spinner` |
| `budget` | `double` | it has decimals; `float` loses precision at 160,000,000 |
| `duration` | `int` | `SeekBar.getProgress()` returns `int` |
| `rating` | `float` | `RatingBar.getRating()` returns `float` |
| `watched` | `boolean` | `isChecked()` |
| `approval` | `String` | the text of the selected radio button ("PG-13") |
| `onWatchlist` | `boolean` | `isChecked()` |
| `poster` | `String` | a URL |

**`poster = null` written out explicitly** — even though a `String` is `null` by default, the line documents it: "it may be missing".

```java
    public Movie(String title, Date release, String genre, double budget, int duration,
                 float rating, boolean watched, String approval,
                 boolean onWatchlist, String poster) {
        this.title = title;
        this.release = release;
        this.genre = genre;
        this.budget = budget;
        this.duration = duration;
        this.rating = rating;
        this.watched = watched;
        this.approval = approval;
        this.onWatchlist = onWatchlist;
        this.poster = poster;
    }
```

**Why `this.title = title`:** the parameter has the same name as the field. Without `this`, you would be writing `title = title` — self-assignment, and the field stays `null`.

**The parameter order is positional** and has to be respected exactly:

```
1. String title      6. float rating
2. Date release      7. boolean watched
3. String genre      8. String approval
4. double budget     9. boolean onWatchlist
5. int duration     10. String poster
```

> If you swap two parameters of **the same type**, the compiler won't catch it. The movie still gets created, but with the wrong data.

```java
    @Override
    public String toString() {
        return "Movie{" +
                "title='" + title + '\'' +
                ", release=" + release +
                ", genre='" + genre + '\'' +
                ", budget=" + budget +
                ", duration=" + duration +
                ", rating=" + rating +
                ", watched=" + watched +
                ", approval='" + approval + '\'' +
                ", onWatchlist=" + onWatchlist +
                ", poster='" + poster + '\'' +
                '}';
    }
```

**Why `toString()` matters:** `ArrayAdapter` calls it on every element in order to display the row. Without the override, the list would show `ro.ase.ie.g1097.model.Movie@a1b2c3d`.

**The format** is generated by IntelliJ (**Alt+Insert → toString()**). `'\''` is an escaped apostrophe.

**What you see in the list at `d719ffc`:** all 10 fields on one row, including the poster URL. Ugly, but correct. It gets fixed in chapter 11 with `RecyclerView`.

```java
    public String getTitle() { return title; }
    public void setTitle(String title) { this.title = title; }
    // ... same for all 10

    public boolean isWatched() { return watched; }
    public void setWatched(boolean watched) { this.watched = watched; }

    public boolean isOnWatchlist() { return onWatchlist; }
    public void setOnWatchlist(boolean onWatchlist) { this.onWatchlist = onWatchlist; }

    public Movie() {
    }
}
```

**`isWatched()` and not `getWatched()`** — the JavaBeans convention for `boolean`. In chapter 11, `MovieAdapter` calls `movie.isWatched()`. If you had written `getWatched()`, it does not compile.

**The empty constructor is at the end** — the position doesn't matter to the compiler, but **its existence is mandatory**:

> If you define a constructor with parameters, Java **no longer generates** the no-argument constructor automatically. And `ItemActivity.saveMovie()` does `new Movie();`. Without it, it does not compile.

## 22.2 `MainActivity.java` — the list and navigation

### The constants and fields

```java
public class MainActivity extends AppCompatActivity {

    protected static final String POSITION_EXTRA = "position";
    protected static final String MOVIE_EXTRA = "movie";
```

**Why constants and not a hand-written `"movie"`:** the key is used in two activities. If you write `"movie"` in one place and `"Movie"` in another, you get `null` **with no error at all**.

**Why `protected static final`:**
- `protected` — accessible from `ItemActivity` (they are in the same `activities` package)
- `static` — it belongs to the class, not to the instance
- `final` — it does not change

```java
    private FloatingActionButton fabInsert;
    private ListView listView;
    private ActivityResultLauncher<Intent> launcher;
    private final List<Movie> movies = new ArrayList<>();
    private ArrayAdapter<Movie> movieAdapter;
```

**Why fields and not local variables:** they are used in several methods (`onCreate`, `initControls`, `initListeners`).

**Why `final` on `movies`:** the reference never changes — the same list, only its contents get modified. You can do `movies.add(...)`, but not `movies = ...`.

**Why `List<Movie>` and not `ArrayList<Movie>`:** `List` is the interface. You can swap the implementation at any time without touching the rest of the code.

### `onCreate` — order matters

```java
    @Override
    protected void onCreate(Bundle savedInstanceState) {
        super.onCreate(savedInstanceState);      // 1. the parent's lifecycle
        EdgeToEdge.enable(this);                 // 2. allows drawing under the system bars
        setContentView(R.layout.activity_main);  // 3. builds the view tree
```

**The order is mandatory.** `findViewById` called before `setContentView` returns `null`.

```java
        ViewCompat.setOnApplyWindowInsetsListener(findViewById(R.id.main), (v, insets) -> {
            Insets systemBars = insets.getInsets(WindowInsetsCompat.Type.systemBars());
            v.setPadding(systemBars.left, systemBars.top, systemBars.right, systemBars.bottom);
            return insets;
        });
```

**What it does:** it applies padding equal to the system bars on the **root** (`R.id.main`). Without it, the first row of the list goes under the clock, and the FAB goes under the navigation bar.

**Why on the root:** padding on the root pushes **all** the children into the safe area. On a single child, the others would stay under the bars.

**`return insets`** (not `CONSUMED`) lets the insets travel on.

```java
        addSampleMovies();                                          // 4. fills the list (no UI)

        movieAdapter = new ArrayAdapter<>(this,                     // 5. creates the adapter
                android.R.layout.simple_list_item_1, movies);
        initControls();                                             // 6. findViewById + setAdapter
        initListeners();                                            // 7. wires up the buttons
```

**Why `addSampleMovies` before `new ArrayAdapter`:** the adapter receives the **reference** to the list. By filling it beforehand, the adapter sees the list already full at construction time — you don't need `notifyDataSetChanged()`.

**Why `initControls` after `new ArrayAdapter`:** `initControls` does `listView.setAdapter(movieAdapter)`. If `movieAdapter` were `null`, you'd get a `NullPointerException`.

```java
        launcher = registerForActivityResult(
                new ActivityResultContracts.StartActivityForResult(),
                new ActivityResultCallback<ActivityResult>() {
                    @Override
                    public void onActivityResult(ActivityResult o) {
                        if (o.getResultCode() == RESULT_OK) {
                            Intent intent = o.getData();
                            Movie movie = (Movie) intent.getSerializableExtra(MOVIE_EXTRA);
                            int position = intent.getIntExtra(POSITION_EXTRA, -1);
                            if (position == -1) {
                                movies.add(movie);                 // insert
                            } else {
                                movies.set(position, movie);       // edit
                            }
                            movieAdapter.notifyDataSetChanged();   // ← mandatory
                        }
                    }
                });
    }
```

**`launcher` is initialised AFTER `initListeners()`** — a real trap in the repo. It works only because the listener **does not run at registration**, but on click. By the time the click happens, `launcher` is already initialised.

> If you called `fabInsert.performClick()` right after `initListeners()`, you'd get a `NullPointerException`.

**`getResultCode() == RESULT_OK`** — mandatory. Without that check, when the user presses Back, `getData()` is `null` → NPE.

**`position == -1`** = insert (FAB), `position >= 0` = edit (row click).

**`notifyDataSetChanged()`** — without it, the list does not redraw. The movie is saved, but it never shows up.

### `initControls` — the XML ↔ code link

```java
    private void initControls() {
        fabInsert = findViewById(R.id.floatingActionButton);
        listView = findViewById(R.id.listView);
        listView.setAdapter(movieAdapter);
    }
```

**`findViewById` is generic** in modern Java: `ListView listView = findViewById(R.id.listView);` works without a cast.

**`setAdapter` is the last line** — it binds the data source to the widget.

### `initListeners` — the two actions

```java
    private void initListeners() {
        fabInsert.setOnClickListener(new View.OnClickListener() {
            @Override
            public void onClick(View v) {
                Intent intent = new Intent(MainActivity.this, ItemActivity.class);
                launcher.launch(intent);
            }
        });

        listView.setOnItemClickListener(new AdapterView.OnItemClickListener() {
            @Override
            public void onItemClick(AdapterView<?> parent, View view, int position, long id) {
                Intent intent = new Intent(MainActivity.this, ItemActivity.class);
                intent.putExtra(MOVIE_EXTRA, movies.get(position));
                intent.putExtra(POSITION_EXTRA, position);
                launcher.launch(intent);
            }
        });
    }
```

**`MainActivity.this` and not `this`:** inside the anonymous class, `this` is the anonymous class — which is not a `Context`. `new Intent(this, ...)` would fail.

**`launcher.launch(intent)` and not `startActivity(intent)`:** the second one starts the activity, but **you get nothing back**.

**FAB → `Intent` with no extras** → `ItemActivity` enters insert mode.
**Row click → `Intent` with `MOVIE_EXTRA` + `POSITION_EXTRA`** → `ItemActivity` enters edit mode.

### `addSampleMovies` — the demo data

```java
    private void addSampleMovies() {
        movies.add(new Movie(
                "Inception",
                new GregorianCalendar(2010, Calendar.JULY, 16).getTime(),
                "Sci-Fi",
                160000000,
                148,
                4.5f,
                true,
                "PG-13",
                false,
                "https://example.com/posters/inception.jpg"));
        // ... Toy Story, The Matrix
    }
```

**`GregorianCalendar(2010, Calendar.JULY, 16)`** — months are indexed **from 0**: `JULY` = 6, not 7. That is why the constants are used.

**`.getTime()`** — `GregorianCalendar` **is** a `Calendar`, not a `Date`. `getTime()` extracts the milliseconds.

**`4.5f`** — a `float` literal. `4.5` would be a `double` and would not fit the `float` parameter without a cast.

### `initListeners` — four listeners

```java
    private void initListeners() {
        etRelease.setOnClickListener(v -> showReleaseDatePicker());
        btMovieAction.setOnClickListener(v -> saveMovie());

        swWatched.setOnCheckedChangeListener((buttonView, isChecked) ->
                tvWatchedValue.setText(isChecked ? "Yes" : "No"));

        sbDuration.setOnSeekBarChangeListener(new SeekBar.OnSeekBarChangeListener() {
            @Override
            public void onProgressChanged(SeekBar seekBar, int progress, boolean fromUser) {
                tvDurationValue.setText(progress + " min.");
            }
            @Override public void onStartTrackingTouch(SeekBar seekBar) { }
            @Override public void onStopTrackingTouch(SeekBar seekBar) { }
        });
    }
```

**`setOnClickListener` on an `EditText`** — an `EditText` takes focus on touch, not a click. But `setOnClickListener` still works: on the first touch it takes focus **and** fires the click.

**`SeekBar` gets an anonymous class** (3 methods), **`Switch` gets a lambda** (1 method).

**`fromUser` is ignored** — the text is updated even when the value comes from code (`setProgress` in `fillForm`). That's correct: you want the label to always reflect the value.

### `showReleaseDatePicker`

```java
    private void showReleaseDatePicker() {
        String current = etRelease.getText().toString();
        if (!current.isEmpty()) {
            try {
                Date parsed = dateFormat.parse(current);
                if (parsed != null)
                    releaseCal.setTime(parsed);
            } catch (ParseException ignored) { }
        }

        new DatePickerDialog(this,
                (view, year, month, day) -> {
                    releaseCal.set(year, month, day);
                    etRelease.setError(null);
                    etRelease.setText(dateFormat.format(releaseCal.getTime()));
                },
                releaseCal.get(Calendar.YEAR),
                releaseCal.get(Calendar.MONTH),
                releaseCal.get(Calendar.DAY_OF_MONTH)
        ).show();
    }
```

**The flow:**
1. read the current text;
2. if it isn't empty, parse it into `releaseCal`;
3. open the dialog positioned on `releaseCal`;
4. on confirmation, update `releaseCal` and the text.

**`month` is 0-indexed here too** — `DatePickerDialog` returns the value `Calendar.set` expects directly. No `-1`.

**`catch (ParseException ignored) { }`** — if the user typed "abc", we ignore it and start from the previous date. An empty `catch` is acceptable **only** when the error does not change the behaviour you want.

### `saveMovie` — building the model

```java
    private void saveMovie() {
        Movie movie = new Movie();
        movie.setTitle(etTitle.getText().toString());
        movie.setRelease(releaseCal.getTime());
        movie.setGenre(spGenre.getSelectedItem().toString());
        movie.setBudget(Double.parseDouble(etBudget.getText().toString()));
        movie.setDuration(sbDuration.getProgress());
        movie.setRating(rbRating.getRating());
        movie.setWatched(swWatched.isChecked());
        movie.setOnWatchlist(cbonWatchList.isChecked());
        movie.setPoster(etPoster.getText().toString());

        for (int index = 0; index < rgApproval.getChildCount(); index++) {
            RadioButton rb = (RadioButton) rgApproval.getChildAt(index);
            if (rb.isChecked()) {
                movie.setApproval(rb.getText().toString());
                break;
            }
        }

        Intent intent = new Intent();
        intent.putExtra(MainActivity.MOVIE_EXTRA, movie);
        if (position != -1)
            intent.putExtra(MainActivity.POSITION_EXTRA, position);
        setResult(RESULT_OK, intent);
        finish();
    }
```

**The source of each field:**

| Model | Source | Method |
|---|---|---|
| `title` | `etTitle` | `getText().toString()` |
| `release` | `releaseCal` | `getTime()` — **not** `etRelease` |
| `genre` | `spGenre` | `getSelectedItem().toString()` |
| `budget` | `etBudget` | `Double.parseDouble(...)` |
| `duration` | `sbDuration` | `getProgress()` |
| `rating` | `rbRating` | `getRating()` |
| `watched` | `swWatched` | `isChecked()` |
| `onWatchlist` | `cbonWatchList` | `isChecked()` |
| `poster` | `etPoster` | `getText().toString()` |
| `approval` | `rgApproval` | you iterate the children |

**Why `releaseCal` and not `etRelease`:** the calendar is the source of truth. The text can be empty or invalid.

**The radio loop is generic** — you add a button in XML, the code sees it with no changes.

**`if (position != -1)`** — in insert mode you don't send the position; `MainActivity` reads its absence as "add at the end".

**`setResult(RESULT_OK, intent)` + `finish()`** — the mandatory pair. Without `setResult`, `MainActivity` receives `RESULT_CANCELED` and does nothing.

### The real bugs in this file

| Line | Bug | What happens |
|---|---|---|
| `Double.parseDouble(etBudget.getText().toString())` | empty field → `""` | `NumberFormatException` → crash |
| `dateFormat.format(existing.getRelease())` in `fillForm` | `release` is `null` | `NullPointerException` → crash |
| `String.valueOf(existing.getBudget())` in `fillForm` | 160000000.0 | it displays `1.6E8` |

**All three are real at `d719ffc`** and documented in chapters 07 and 09. If the exam asks you to fix them, you know exactly what to do.

## 22.4 `activity_main.xml` — the list screen

```xml
<FrameLayout xmlns:android="http://schemas.android.com/apk/res/android"
    xmlns:app="http://schemas.android.com/apk/res-auto"
    xmlns:tools="http://schemas.android.com/tools"
    android:id="@+id/main"
    android:layout_width="match_parent"
    android:layout_height="match_parent"
    android:orientation="horizontal"
    tools:context=".activities.MainActivity">
```

**`FrameLayout`** — it stacks the children on top of each other. The order in XML = the drawing order.

**`android:id="@+id/main"`** — used by the insets in code. Without it, `findViewById(R.id.main)` returns `null`.

**`android:orientation="horizontal"`** — an **invalid attribute** on `FrameLayout`. Ignored by Android, a lint warning. A leftover from an earlier `LinearLayout`.

**`tools:context`** — only for the preview, stripped at build time.

```xml
    <ListView
        android:id="@+id/listView"
        android:layout_width="match_parent"
        android:layout_height="match_parent"
        android:entries="@array/items" />
```

**`android:entries`** — it fills the list from XML with 20 "Item 1..20". At runtime, `listView.setAdapter(movieAdapter)` **replaces it**. It stays for the preview.

```xml
    <com.google.android.material.floatingactionbutton.FloatingActionButton
        android:id="@+id/floatingActionButton"
        android:layout_width="wrap_content"
        android:layout_height="wrap_content"
        android:layout_gravity="bottom|end"
        android:layout_margin="16dp"
        android:contentDescription="Add"
        app:srcCompat="@drawable/outline_add_24" />
</FrameLayout>
```

**`layout_gravity="bottom|end"`** — the position of the **element** inside the parent. `end` respects the reading direction (RTL).

**`contentDescription`** — mandatory for images, otherwise lint errors out. The text is read by TalkBack.

**`app:srcCompat`** — the compatible variant for `VectorDrawable`.

**The order:** `ListView` first, FAB second → the FAB is **on top of** the list. The other way round, the list would cover it.

```
    ├── MaterialCardView [Basics]

    ├── MaterialCardView [Production]
    │   ├── TextView "Production"
    │   ├── TextView tvBudget + TextInputLayout(prefixText="$ ") + etBudget
    │   ├── LinearLayout (tvDuration + tvDurationValue)
    │   ├── SeekBar sbDuration (max=300, min=0)
    │   └── LinearLayout ("0 min" / "300 min")
    ├── MaterialCardView [Your verdict]
    │   ├── TextView "Your verdict"
    │   ├── TextView tvRating + RatingBar rbRating (5 stars, step 0.5)
    │   ├── View (separator 1dp)
    │   ├── LinearLayout (tvWatched + tvWatchedValue | swWatched | cbOnWatchList)

    │   ├── TextView "Poster"
    │   └── TextInputLayout(startIcon=gallery) + etPoster
    └── MaterialButton btnMovieAction (60dp, cornerRadius 30dp)
```

### The blocks worth explaining

**`ScrollView` with a single child:**

```xml
<ScrollView ...
    android:id="@+id/main"
    android:background="?attr/colorSurface"
    android:fillViewport="true">
```

> A `ScrollView` is allowed **exactly one child**. Two → `ScrollView can host only one direct child`.

**`?attr/colorSurface`** — the colour from the theme (white in light, dark grey in dark). `#FFFFFF` would break dark mode.

**`fillViewport="true"`** — it stretches the content to fill the screen if it is shorter.

**`TextInputLayout` with a fixed label:**

```xml
<TextView android:id="@+id/tvTile" android:text="Title" ... />

<com.google.android.material.textfield.TextInputLayout
    style="@style/Widget.Material3.TextInputLayout.OutlinedBox"
    app:hintEnabled="false"
    app:endIconMode="clear_text">
    <com.google.android.material.textfield.TextInputEditText
        android:id="@+id/etTitle"
        android:hint="Movie title"
        android:inputType="textCapWords" />
</com.google.android.material.textfield.TextInputLayout>
```

**`hintEnabled="false"`** — it disables the floating hint. Otherwise you have **two** labels: the `TextView` above and the hint inside the outline.

**`endIconMode="clear_text"`** — an "X" on the right that clears the text. It does **not** reset the model — only the `EditText`.

**`tvTile`** — a typo in the repo for "tvTitle". It is not used in code.

**`Spinner` inside an outlined `MaterialCardView`:**

```xml
<com.google.android.material.card.MaterialCardView
    style="?attr/materialCardViewOutlinedStyle"
    android:layout_height="56dp"
    app:cardBackgroundColor="@android:color/transparent"
    app:cardCornerRadius="4dp"
    app:strokeColor="?attr/colorOutline">

    <Spinner android:id="@+id/spGenre"
        android:entries="@array/movie_genre"
        android:spinnerMode="dropdown" />
</com.google.android.material.card.MaterialCardView>
```

**The trick:** the native `Spinner` has no outline. You wrap it in an outlined card so it looks like the other `OutlinedBox` fields (1dp outline, 4dp corners, 56dp height).

**Here `entries` stays** — `ItemActivity` does not call `spGenre.setAdapter(...)`.

**`SeekBar`:**

```xml
<SeekBar
    android:id="@+id/sbDuration"
    android:max="300"
    android:min="0"
    android:progressTint="?attr/colorPrimary"
    android:thumbTint="?attr/colorPrimary" />
```

**`android:min` is available from API 26.** `minSdk 33`, so it works.

**The two labels "0 min" / "300 min" are hardcoded** — if you change `max`, you have to change them too.

**`RatingBar`:**

```xml
<RatingBar
    android:id="@+id/rbRating"
    android:numStars="5"
    android:stepSize="0.5"
    android:progressTint="#FFC107"
    android:secondaryProgressTint="#FFC107"
    android:progressBackgroundTint="?attr/colorOutlineVariant" />
```

**`#FFC107` hardcoded** — star yellow, a fixed meaning, not a theme role. An accepted exception.

**`stepSize="0.5"`** — half stars. `getRating()` returns a `float`.

**`RadioGroup` inside a `HorizontalScrollView`:**

```xml
<HorizontalScrollView android:scrollbars="none">
    <RadioGroup android:id="@+id/rgApproval"
        android:orientation="horizontal">
        <com.google.android.material.radiobutton.MaterialRadioButton
            android:id="@+id/rbGeneral"
            android:checked="true"
            android:text="G" />
        <!-- PG, PG-13, R, NC-17 -->
    </RadioGroup>
</HorizontalScrollView>
```

**`HorizontalScrollView`** — 5 buttons do not fit on a 360dp screen.

**`android:checked="true"` on the first one** — `rgApproval` **always** has a value. You cannot save a movie without a guidance rating.

**`MaterialButton`:**

```xml
<com.google.android.material.button.MaterialButton
    android:id="@+id/btnMovieAction"
    style="@style/Widget.Material3.Button"
    android:layout_height="60dp"
    app:cornerRadius="30dp"
    app:icon="@android:drawable/ic_menu_save"
    app:iconGravity="textStart" />
```

**`cornerRadius = height / 2`** = pill. `Widget.Material3.Button` **is** the filled variant.

```xml
<com.google.android.material.card.MaterialCardView
    android:layout_marginHorizontal="12dp"
    android:layout_marginVertical="6dp"
    app:cardCornerRadius="16dp"
    app:cardElevation="3dp"
    app:cardUseCompatPadding="true">

    <LinearLayout android:orientation="horizontal" android:padding="12dp">

            android:id="@+id/moviePoster"

            android:orientation="vertical" android:layout_marginStart="12dp">

            <TextView android:id="@+id/movieTitle" android:textSize="20sp"
                android:textStyle="bold" android:maxLines="2" android:ellipsize="end" />

            <TextView android:id="@+id/movieSubtitle" android:textSize="14sp" />

            <LinearLayout android:orientation="horizontal">
                <RatingBar android:id="@+id/movieRating"
                    style="?android:attr/ratingBarStyleSmall"
                    android:isIndicator="true" />
                <TextView android:id="@+id/movieRatingValue" />
            </LinearLayout>

            <TextView android:id="@+id/movieFacts" android:textSize="13sp" />

            <com.google.android.material.chip.ChipGroup android:id="@+id/movieStatusGroup">
                <Chip android:id="@+id/chipApproval" android:clickable="false" />
                <Chip android:id="@+id/chipWatched" android:clickable="false" />
                <Chip android:id="@+id/chipWatchlist" android:clickable="false" />
            </ChipGroup>
        </LinearLayout>
    </LinearLayout>

```

**`cardElevation="3dp"`** — here the shadow is **present**, unlike the cards in the form. This is a list item, not a section.

**`ImageView` 96×140dp** — a ~2:3 ratio, like a poster. `scaleType="centerCrop"` fills without distorting.

**`layout_width="0dp"` + `layout_weight="1"`** on the text column — it takes all the space left after the poster.

**`maxLines="2"` + `ellipsize="end"`** — long titles get truncated with "…".

**`isIndicator="true"`** — the stars are display only, not input. No listener needed.

**`clickable="false"` on the chips** — they are labels, not buttons.

**`ensureMinTouchTargetSize="false"`** — otherwise Material pushes them to 48dp and breaks the layout.

## 22.7 How it all fits together — the complete flow

```
START
  MainActivity.onCreate
    ├── setContentView(activity_main)
    ├── insets on R.id.main
    ├── addSampleMovies()            → 3 movies in `movies`
    ├── new ArrayAdapter(movies)     → movieAdapter
    ├── initControls()               → findViewById + setAdapter
    ├── initListeners()              → FAB + item click
    └── registerForActivityResult    → launcher

PRESS THE FAB
  onClick → Intent(MainActivity → ItemActivity)
          → launcher.launch(intent)
            ↓
  ItemActivity.onCreate
    ├── setContentView(activity_item)
    ├── initControls()               → 13 × findViewById
    ├── initListeners()              → date picker, save, switch, seekbar
    └── existing == null             → insert mode (empty form)

FILL IN + SAVE
  saveMovie()
    ├── new Movie()
    ├── 10 × setter from the widgets
    ├── loop over rgApproval
    ├── Intent with MOVIE_EXTRA (no POSITION_EXTRA)
    ├── setResult(RESULT_OK, intent)
    └── finish()
          ↓
  MainActivity.onActivityResult
    ├── resultCode == RESULT_OK ?
    ├── position == -1  → movies.add(movie)
    └── movieAdapter.notifyDataSetChanged()
          ↓
  ListView redraws → the movie appears

ROW CLICK
  onItemClick(position)
    ├── Intent with MOVIE_EXTRA + POSITION_EXTRA
    └── launcher.launch(intent)
          ↓
  ItemActivity.onCreate
    ├── existing != null
    ├── position = ...
    ├── fillForm(existing)          → fills the 10 fields
    └── setTitle + "Update Movie" button

EDIT + UPDATE
  saveMovie()
    ├── Intent with MOVIE_EXTRA + POSITION_EXTRA
    └── setResult + finish()
          ↓
  MainActivity.onActivityResult
    ├── position != -1 → movies.set(position, movie)
    └── notifyDataSetChanged()
```

## 22.8 What to remember from each file

## Chapter 22 summary

- The model never touches the UI; the activities contain no row logic.
- `onCreate`: `super` → `setContentView` → `findViewById` → the rest.
- `releaseCal` is the source of truth, not the text in the `EditText`.
- The loop over the `RadioGroup` makes the code generic — you add buttons, the code sees them.
- `setResult(RESULT_OK)` + `finish()` is the mandatory pair.
- `notifyDataSetChanged()` after any change to the list.
- `movie_item.xml` exists but is not wired up — preparation for the next lab.
- Three real bugs: empty budget, `null` `release`, scientific notation.
